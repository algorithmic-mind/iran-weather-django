## ۱. کار برنامه و مسیر یک درخواست

کاربر در فرم، کشور و استان و در صورت نیاز شهر را انتخاب می‌کند. مرورگر یک درخواست `GET` به `/` می‌فرستد. تابع `home` شناسه‌ها را از پایگاه‌داده بررسی می‌کند، مختصات مناسب را به `get_weather` می‌دهد و نتیجه را به قالب می‌فرستد.

```text
مرورگر و فرم GET
      ↓
config/urls.py  →  weather/views.py:home
                       ↓                 ↓
               مدل‌های مکان       weather/services.py
                       ↓                 ↓
                  پایگاه SQLite       Open-Meteo
                         \             /
                         قالب HTML + CSS
```

**یک مثال:** با انتخاب «ایران ← البرز ← کرج»، view بررسی می‌کند که کرج واقعاً زیرمجموعهٔ البرز است؛ سپس مختصات کرج برای API استفاده می‌شود. اگر شهر انتخاب نشود، مختصات خود استان به کار می‌رود. انتخاب اولیهٔ برنامه «ایران، البرز، کل استان» است.

## ۲. راه‌اندازی و پوشه‌ها

پایتون ۳٫۱۲ یا جدیدتر لازم است. در PowerShell و از ریشهٔ پروژه:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py runserver
```

آدرس صفحهٔ اصلی `http://127.0.0.1:8000/` است. دستور `migrate` جدول‌ها و داده‌های اولیه را ایجاد می‌کند؛ لازم نیست JSON مکان‌ها را دستی وارد کنید.

| مسیر | مسئولیت |
|:---|:---|
| `manage.py` | اجرای دستورهای Django |
| `config/settings.py` | تنظیمات برنامه، پایگاه داده، زبان و فایل‌ها |
| `config/urls.py` | وصل‌کردن `/` و `/admin/` به کد مربوط |
| `weather/models.py` | تعریف مکان‌ها و تصویر استان |
| `weather/views.py` | پردازش انتخاب کاربر و ساخت دادهٔ صفحه |
| `weather/services.py` | ارتباط با API و تفسیر کد هوا |
| `weather/jalali.py` | تبدیل تاریخ میلادی API به شمسی |
| `templates/weather/home.html` | ساخت HTML صفحه |
| `static/weather/style.css` | ظاهر اختصاصی |
| `static/vendor/` | Bootstrap، آیکون‌ها و وزیر به شکل محلی |
| `media/provinces/` | فایل عکس استان‌ها |
| `weather/tests.py` | آزمون رفتارهای اصلی |

## ۳. تنظیمات و آدرس‌ها

در `config/settings.py`، برنامهٔ `weather` داخل `INSTALLED_APPS` ثبت شده است. `DATABASES` به SQLite اشاره می‌کند؛ بنابراین برای اجرای محلی به نصب سرور پایگاه‌داده نیاز نیست. `LANGUAGE_CODE = "fa-ir"`، `TIME_ZONE = "Asia/Tehran"` و `USE_TZ = True` تنظیمات زبان و زمان هستند.

فایل‌های **static** شامل CSS و فونت و آیکون هستند و با `STATIC_URL` و `STATICFILES_DIRS` پیدا می‌شوند. فایل‌های **media** عکس‌هایی هستند که در `ImageField` ثبت می‌شوند؛ مسیر آن‌ها در `MEDIA_ROOT` قرار دارد. در حالت توسعه، `config/urls.py` فایل‌های media را سرو می‌کند. در استقرار واقعی باید وب‌سرور این فایل‌ها را ارائه دهد.

در همان فایل، متغیرهای محیطی `DJANGO_SECRET_KEY`، `DJANGO_DEBUG` و `DJANGO_ALLOWED_HOSTS` خوانده می‌شوند. پیش‌فرض‌ها برای اجرای محلی‌اند؛ پیش از انتشار عمومی، مقدار امن برای کلید و میزبان تعیین کنید و debug را خاموش کنید.

`config/urls.py` تنها دو مسیر اصلی دارد:

```python
path("admin/", admin.site.urls)
path("", home, name="home")
```

## ۴. مدل‌های کشور، استان و شهر

در `weather/models.py` کلاس انتزاعی `Coordinates` دو فیلد `latitude` و `longitude` دارد. چون `abstract = True` است، جدول جداگانه‌ای نمی‌سازد؛ این دو فیلد در هر سه مدل دیگر قرار می‌گیرند.

```text
Country 1 ── n Province 1 ── n City
                    │
                    └── image + image_caption + image_credit + image_license + image_source
```

`Province.country` و `City.province` از نوع `ForeignKey` هستند. `on_delete=models.CASCADE` یعنی حذف یک کشور، استان‌های آن را هم حذف می‌کند؛ حذف استان نیز شهرهای آن را حذف می‌کند. محدودیت `UniqueConstraint` اجازه نمی‌دهد دو استان هم‌نام در یک کشور یا دو شهر هم‌نام در یک استان ثبت شوند. اعتبارسنج‌های مختصات نیز عرض را در بازهٔ `-90..90` و طول را در بازهٔ `-180..180` نگه می‌دارند.

در مدل استان، `image` از نوع `ImageField` است و عکس را زیر `media/provinces/` نگه می‌دارد. `image_caption` توضیح کوتاهی دربارهٔ مکان یا منظرهٔ عکس است و روی هدر نمایش داده می‌شود. فیلدهای `image_credit`، `image_license`، `image_license_url` و `image_source` اطلاعات انتساب را برای پایین صفحه نگه می‌دارند.

## ۵. دادهٔ اولیه و تصاویر استان‌ها

فایل `weather/data/iran_locations.json` دادهٔ ایران، ۳۱ استان و ۱۱۳۷ شهر/مکان را دارد. مهاجرت `0002_seed_iran.py` این JSON را می‌خواند و رکوردها را می‌سازد. مهاجرت‌های بعدی فیلدهای تصویر را اضافه می‌کنند و با خواندن `weather/data/photo_credits.json` عکس هر استان را به رکورد آن وصل می‌کنند. مهاجرت `0008_province_image_caption.py` نیز توضیح هر عکس را از `weather/data/province_captions.json` ثبت می‌کند. خود فایل‌های عکس در `media/provinces/` قرار دارند.

**تفاوت مهم:** در پایگاه‌داده، فیلد تصویر مسیر نسبی فایل را نگه می‌دارد؛ خود تصویر در فایل‌سیستم است. پس برای انتقال کامل پروژه، هم پایگاه‌داده و هم پوشهٔ `media` را نگه دارید.

برای تغییر عکس یک استان، با دستور زیر کاربر مدیر بسازید و به `/admin/` بروید:

```powershell
.\.venv\Scripts\python.exe manage.py createsuperuser
```

منابع، مجوزها و نام پدیدآورندگان تصاویر در [فهرست تصاویر](../weather/data/photo_credits.json) آمده‌اند. راهنمای منبع دادهٔ جغرافیایی نیز [اینجاست](../weather/data/README.md).

## ۶. سرویس Open-Meteo و کش

تابع `get_weather(latitude, longitude)` در `weather/services.py` با `urlencode` نشانی [API پیش‌بینی Open-Meteo](https://open-meteo.com/en/docs) را می‌سازد. پارامتر `current` دما، رطوبت، دمای محسوس، بارش، سرعت باد، روز/شب و کد وضعیت را می‌خواهد. پارامتر `daily` بیشینه و کمینهٔ دما، بارش و کد وضعیت سه روز را می‌خواهد. `timezone=Asia/Tehran` باعث می‌شود زمان پاسخ برای ایران باشد.

```python
weather = get_weather(city.latitude, city.longitude)
temperature = weather["current"]["temperature_2m"]
```

API برای وضعیت هوا عدد WMO برمی‌گرداند. `weather_description` آن عدد را به توضیح فارسی و نام آیکون Bootstrap تبدیل می‌کند؛ مثلاً `0` آفتابی و `61` بارانی است. دادهٔ روزانه با `zip(..., strict=True)` کنار هم قرار می‌گیرد تا طول نابرابر آرایه‌ها بی‌صدا نادیده گرفته نشود.

برای هر مختصات یک کلید کش ساخته می‌شود. دادهٔ موفق به مدت **۶۰۰ ثانیه (۱۰ دقیقه)** ذخیره می‌شود تا بازکردن مکرر صفحه درخواست تازه به API نفرستد. درخواست شبکه مهلت **۸ ثانیه** دارد. اگر شبکه، JSON یا ساختار پاسخ مشکل داشته باشد، `WeatherUnavailable` بالا می‌رود و view به‌جای شکست صفحه، پیام مناسب نمایش می‌دهد. این کش پیش‌فرض Django در حافظهٔ فرایند است؛ با راه‌اندازی دوبارهٔ سرور خالی می‌شود.

## ۷. View و اعتبارسنجی انتخاب‌ها

تابع `home(request)` در `weather/views.py` یک **Function-Based View** ساده است. شناسه‌ها از `request.GET` می‌آیند؛ تابع کوچک `_id` مقدار نامعتبر را به `None` تبدیل می‌کند. پس از انتخاب کشور، استان فقط از استان‌های همان کشور جست‌وجو می‌شود؛ شهر هم فقط از شهرهای همان استان. بنابراین تغییر دستی شناسه در URL نمی‌تواند شهر یک استان دیگر را به‌عنوان انتخاب معتبر جا بزند.

ترتیب انتخاب مکان برای هواشناسی چنین است:

```python
location = city or province or country
```

بعد از دریافت هوا، view با توابع `jalali_datetime` و `jalali_date` زمان‌ها را برای نمایش آماده می‌کند و متغیرهای لازم را با `render` به قالب می‌فرستد. خود فرم با GET کار می‌کند؛ URL انتخاب را نشان می‌دهد و قابل ذخیره یا اشتراک‌گذاری است. کد جاوااسکریپت پیچیده‌ای وجود ندارد؛ تغییر کشور/استان فقط فرم را دوباره ارسال می‌کند.

## ۸. تاریخ شمسی

Open-Meteo تاریخ را به شکل میلادی ISO می‌فرستد. در `weather/jalali.py`، `date.fromisoformat` یا `datetime.fromisoformat` آن را می‌خواند و `jdatetime.date.fromgregorian` روز شمسی را به دست می‌آورد. در پایان `translate` رقم‌های لاتین را به فارسی تبدیل می‌کند.

```text
2026-10-15       →  ۱۴۰۵/۰۷/۲۳
2026-10-15T12:30 →  ۱۴۰۵/۰۷/۲۳، ۱۲:۳۰
```

این تبدیل فقط در **نمایش** انجام می‌شود؛ پاسخ API و ذخیرهٔ دادهٔ هوا تغییر نمی‌کند. زمان ورودی از API با منطقهٔ زمانی ایران درخواست شده است.

## ۹. قالب، فایل‌های محلی و پنل مدیریت

`templates/weather/home.html` صفحه را با `lang="fa"` و `dir="rtl"` می‌سازد. سه stylesheet محلی از `static/vendor/` بارگذاری می‌شوند: Bootstrap RTL، Bootstrap Icons و فونت وزیر. `static/weather/style.css` رنگ، فاصله، کارت‌ها، چیدمان موبایل و تصویر هدر را تنظیم می‌کند.

در هدر، `province.image.url` عکس استان را نشان می‌دهد و `province.image_caption` مکان یا منظرهٔ عکس را معرفی می‌کند. نام پدیدآورنده و پیوند مجوز پایین صفحه دیده می‌شوند. اگر هوا در دسترس نباشد، عکس و فرم همچنان نمایش داده می‌شوند و پیام خطا زیر فرم می‌آید. اگر استان تصویری نداشته باشد، پس‌زمینهٔ گرادیانی دیده می‌شود.

`weather/admin.py` سه مدل را در پنل مدیریت ثبت کرده است. می‌توانید نام‌ها، مختصات، تصویر، توضیح کوتاه تصویر و اطلاعات منبع عکس را از آنجا ویرایش کنید. فایل‌های ظاهری و تصاویر محلی‌اند؛ **هوای زنده** همچنان به ارتباط اینترنتی سرور با Open-Meteo وابسته است.

## ۱۰. آزمون، توسعه و خطاهای رایج

```powershell
.\.venv\Scripts\python.exe manage.py test
.\.venv\Scripts\python.exe manage.py check
```

آزمون‌های `weather/tests.py` انتخاب پیش‌فرض، ردکردن شهرِ متعلق به استان دیگر، پیام خطای سرویس، وجود ۳۱ تصویر اولیه و تبدیل شمسی را بررسی می‌کنند. در آزمون‌های صفحه، `get_weather` با `patch` جایگزین می‌شود تا نتیجه به اینترنت وابسته نباشد.

برای افزودن کشور یا شهر جدید، از پنل مدیریت رکورد و مختصات را ثبت کنید. برای افزودن شاخص هواشناسی تازه، ابتدا نام پارامتر را به درخواست `current` یا `daily` در `services.py` اضافه کنید، سپس آن را در `home.html` نمایش دهید. برای تغییر آیکون وضعیت، تابع `weather_description` را ویرایش کنید.

| نشانه | نقطهٔ بررسی |
|:---|:---|
| صفحه باز می‌شود ولی هوا نیست | ارتباط سرور با Open-Meteo و پیام خطا را بررسی کنید. |
| عکس استان دیده نمی‌شود | `province.image`، فایل متناظر در `media/provinces/` و سرو شدن media را بررسی کنید. |
| فونت یا آیکون دیده نمی‌شود | فایل‌های `static/vendor/` و تنظیمات static را بررسی کنید. |
| شهرهای استان جدید در فهرست نیستند | ابتدا استان را انتخاب کنید تا فرم دوباره بارگذاری شود. |
| تغییر مدل در پایگاه‌داده دیده نمی‌شود | `makemigrations` و سپس `migrate` را اجرا کنید. |

### نقشهٔ مطالعهٔ پیشنهادی

برای یادگیری، فایل‌ها را به این ترتیب بخوانید: `config/urls.py` ← `weather/views.py` ← `weather/models.py` ← `weather/services.py` ← `weather/jalali.py` ← `templates/weather/home.html` ← `weather/tests.py`. در هر مرحله یک انتخاب شهر را از URL تا خروجی HTML دنبال کنید.
